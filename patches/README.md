# Proposed patches for other owners' files

`eve_core_owner_only_unlock.patch` is for Foxy, the owner of `scripts/ai/eve_core.gd`. `EveBrainCell.unlock()` is public and ungated, so any caller can unlock a cell even though `EveCore.refresh_lock()` only unlocks for the owner. The patch makes `unlock()` itself owner-only. It returns bool, so existing callers that ignore the result keep working.
Apply: `git apply patches/eve_core_owner_only_unlock.patch`. Verified that it applies to main at 0c12750 and that the full test suite passes with it applied.
**Status 2026-10-17: already applied on `main`** (`git apply --check -R` succeeds). Kept for history only; do not apply again.

## Added by the 2026-10-17 audit (not applied; see docs/AUDIT_2026-10-17.md)
These touch files Foxy owns (land-tools sheet, minimap, v0.12 avatar textures), so they are patches, not edits.
- `land_tools_terraform_owner_check.patch` (`scripts/ui/ui_root.gd`): the land panel calls `Estate.can_terraform(region, true)`, so the region's `owner_only` terraform rule never applies. The patch passes `EveCore.owner_ok()` instead. Behaviour change: with the owner session locked, terraforming an owner_only region is refused. To be superseded by `Tiers.can` (BUILD-7).
- `minimap_redraw_throttle.patch` (`scripts/ui/minimap.gd`): redraw at most 10×/s and never while hidden, instead of every frame.
- `avatar_textures_vram_compression.patch` (`assets/characters/*.import`): `compress/mode` 0 → 2 (VRAM, ETC2/ASTC on Android). Measured: export pack grows 8,831,216 → 10,846,416 bytes (+2.0 MB) because the lossless PNGs are small on disk, but GPU memory for the 10 textures drops from about 41.9 MB (RGBA8 + mips) to about 10.5 MB (calculated). Apply after v0.12, and only if on-device memory matters more than download size.
Each one passes `git apply --check` on main at b280233.

`viewer_parity_hud_hooks.patch` is for Foxy, the owner of `scripts/player.gd`. It adds one line so that `set_flying(true)` does nothing while the player has an opt-in `fly` restriction (`Restrictions.is_restricted`, VIEWER-4; see docs/modules/RESTRICTIONS.md). With no restrictions, behaviour is unchanged.
Apply: `git apply patches/viewer_parity_hud_hooks.patch`. Verified with `git apply --check` on main at 1a07535 and on feature/v012-avatar.

## Added by fix/audit-gates (2026-10-17, not applied: Foxy's files)
- `player_fly_estate_rule.patch` (`scripts/player.gd`, `scripts/hud.gd`): `set_flying(true)` asks `LandGate.can_fly(Tiers.SELF, position)` and emits a new `fly_refused` signal instead of flying; while flying, the player lands if they cross into a no-fly parcel (checked every 15 physics frames). The HUD shows a "Flying is off on this land" toast. The owner and estate managers can always fly.
- `estate_panel_admin_gate.patch` (`scripts/ui/ui_root.gd`): the Region/Estate panel saves through `AdminGate.estate_set(...)`, so only the unlocked owner or an estate manager can change region/parcel settings; others get the "Owner unlock needed." toast.
Both pass `git apply --check` on main, and the full suite passes (0 failures) with both applied.
Damage needs no patch: `CombatZone.is_damage_enabled` (used by player, HUD and Cinder Stalker) now asks `LandGate.damage_enabled`.
- `player_fly_estate_rule.after_viewer.patch`: the same change for a `scripts/player.gd` that already has `viewer_parity_hud_hooks.patch` (both edit `set_flying`). Apply order: `git apply patches/viewer_parity_hud_hooks.patch patches/player_fly_estate_rule.after_viewer.patch`. ## Added by feature/phone-display-media (2026-10-17, not applied; for Foxy)
- `ui_root_display_settings.patch` (`scripts/ui/ui_root.gd`, main HUD): the HUD panels follow Settings > Display. `DisplaySettings.rescale_tree(self, 0.75, 0.7)` maps the HUD's base sizes (24 px text, 80 px buttons) to compact (18 px, 56 px) and scales them up for Large; re-applied on `Settings.display_changed` and whenever a panel is shown. Adds a one-tap **Aa  Large text & buttons** switch at the top of **Create Your Avatar** (first run), **🏝 Welcome Island** and **⚙ Settings**, a **Aa Display, device & voice…** button in Settings, and a MENU entry **Aa Display & device** that opens the new Settings screen. Re-anchors the round menu after rotation. Verified: applies to main and the full suite passes with it applied.
- `face_driver_lip_sync.patch` (`scripts/agent/face_driver.gd`, `scripts/agent/companion_agent.gd`, v0.12 branch `feature/v012-avatar`): `FaceDriver.drive(channels)` lets `LipSync` (scripts/audio/lip_sync.gd) replace the length-estimate talk cycle for 0.2 s per push (blink/smile/brow stay FaceDriver's). The companion registers a `CompanionVoice` listener: lips start on the TTS **started** callback, re-align on word **boundary**, stop on **ended**; with no TTS (or the cloud route) they start immediately. The low-poly HumanoidModel jaw also moves. Respects Settings `voice_fx/lip_sync`. Verified: applies to `feature/v012-avatar` at e9f7e58 merged with this branch, and the full suite passes.
Apply: `git apply patches/<name>.patch` (face patch after v0.12 merges).
