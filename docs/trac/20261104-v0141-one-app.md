# 2026-11-04 · v0.14.1 ONE-APP-1 (Scorpion Viper inside the voxel app)

## What was wrong in v0.14.0
- Owner sign-in only existed on the Security screen (radial menu); the ☰ menu and the avatar screen had no way in.
- "Open Social" opened GitHub releases/latest, and on the SkorpionViper repo "Latest" was still v0.35
  (v0.36-v0.38 were pre-releases). Fixed on GitHub: v0.38 is Latest; v0.35-v0.37 are pre-release, titled superseded.

## Done in v0.14.1
- ☰ "Social (Scorpion Viper)" opens the Scorpion Viper web app INSIDE this app (ViperDevice plugin v3:
  full-screen WebView over the world, "✕ World" closes it). No download link, no browser.
- Bundle: social_web/bundle (Scorpion Viper v0.38 web build, owner record replaced by a placeholder).
  CI copies it into the plugin assets and injects OWNER_PASS_HASH from the secret. Only
  https://appassets.androidplatform.net (served from the APK) loads; outside pages are blocked.
- window.ViperHost in the panel: isEmbedded(), ownerSession(), closePanel(), enterWorld(link) (validated by
  SocialBridge.parse_enter before travel).
- One owner unlock: Avatar screen › "Owner sign-in (SkorpionViper)" (username + password, same PBKDF2 record
  as the social app). The old owner-code row is commented out. The owner state is pushed to the panel.
- Startup log line owner_hash_loaded=true|false (no secret); clear message when the record is missing.
